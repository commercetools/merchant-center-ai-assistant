# Plan amendments suggested by changes A, B, U, X

Each item says which plan file and what is wrong or missing, with the evidence.

1. **`plans/02-target-architecture.md` section 2, service row: `CTP_REGION (inherited)` is wrong.** With `inheritAs.apiClient.scopes` Connect injects `CTP_API_URL`, `CTP_AUTH_URL`, `CTP_CLIENT_ID`, `CTP_CLIENT_SECRET`, `CTP_PROJECT_KEY`, `CTP_SCOPE` only (https://docs.commercetools.com/connect/modify-connector.md). Do not declare or require `CTP_REGION`; build the SDK client from `CTP_API_URL`/`CTP_AUTH_URL`. Spec C's `readConfiguration()` must follow this. The Merchant Center region is a separate key, `CLOUD_IDENTIFIER`.
2. **`plans/00-overview.md` D8 ("Connect forwards it to `MC_AUDIENCE`") is not what the docs say.** `CONNECT_SERVICE_URL` is documented only as a variable of the `postDeploy`/`preUndeploy` scripts of a service application (https://docs.commercetools.com/connect/automation-scripts.md), not of the running service. The service therefore cannot read its own origin at runtime; `MC_AUDIENCE` and `CHAT_SERVICE_ENDPOINT_URL` are set by a configuration redeploy (spec U `finalize`). Spec D must keep "fail closed until `MC_AUDIENCE` is set" and must not try to derive the audience from `CONNECT_SERVICE_URL` or from request headers.
3. **`plans/owner-questions.md` Q16 and `plans/00` R5 ignore agent configuration.** Git status shows `.claude/` staged. Add `.claude/`, `CLAUDE.md`, `scripts/labs-gate.sh`, `scripts/internal/`, `scripts/internal-paths.json` to the removed-from-publication list (single source: `scripts/internal-paths.json`, change A).
4. **`plans/04-workflow.md` section 5 (deployed testing).** "`deployment create --type sandbox`" works only for a **published** Connector; a ConnectorStaged cannot be deployed to sandbox (https://docs.commercetools.com/connect/deployment-behavior-and-environments.md). Dev loop = `connectorstaged preview` (needs `isPreviewable`) or `stage` -> `publish` -> sandbox. Also note the update chain (tag -> `connectorstaged update` -> `publish` -> `redeploy --updateConnector`).
5. **`plans/manual-steps.md` M13 vs rehearsals.** M13 says the tag is pushed only after the repo is public, but sandbox rehearsals in spec U/V need a repo URL Connect can clone. Add M15 (private staging repository + access for `connect-mu`). Also add M14 (Docker daemon) to the Definition of Done in `plans/04-workflow.md` section 4: `commercetools connect validate` needs it.
6. **`plans/02` section 2, frontend rows.** Confirm for the Custom View: keys `CUSTOM_VIEW_ID` + `CLOUD_IDENTIFIER`, no entry-point path (deployment doc), although a generic starter listing shows `ENTRY_POINT_URI_PATH` for views. Replace `CHAT_SERVICE_ENDPOINT_URL` "required" by "optional with reserved default `https://not-configured.invalid/service`" so phase 1 can deploy without the service URL. Also `inheritAs.apiClient` is a connector-wide top-level key (not per application).
7. **`plans/02` section 1 layout.** Add `docs/` (runbook, written by U/W), `scripts/connect/` (U), and note that `scripts/` carries its own non-root `package.json` (name `ai-assistant-scripts`, for `yaml`); this is compatible with "no npm workspaces" because there is no root manifest.
8. **`plans/00` D7 version pin.** `@commercetools-frontend/create-mc-app@latest` is 27.13.0 (2026-10-08); the plan pins 27.9.6 (the legacy mc-app). Fine, but scaffolds must be treated as reference only (they add sample code, `AGENTS.md`, `CLAUDE.md`, `.env`). `composed-apps` moves 25.1.0 -> 27.9.6.
9. **`plans/05-data-persistence.md` caveat 1 (Custom Object size).** The documented limit is a general JSON document limit of 16 MB (recommended average 100 KB, large documents not above 2 MB) (https://docs.commercetools.com/api/limits.md#json-document-size); there is no smaller special limit for Custom Objects. The 800 KB chunking from Firestore is therefore not forced by the platform; spec E/N should size chunks from performance guidance, not from a 800 KB constraint.
10. **`plans/03-spec-dependency-map.md` row U.** Add F (the `postDeploy` Vertex check uses the credentials loader) and E (lifecycle probe uses a Custom Object container, `ai-assistant-lifecycle`) to "Needs" - both are earlier waves, so no scheduling impact. Row X: note that the pruned tree is built from `git archive`, not from a fresh clone.
11. **`plans/04-workflow.md` section 4, Definition of Done.** Add `node scripts/check-repo-rules.mjs` and `node scripts/check-connect-layout.mjs` next to `spdx-check.mjs`.
12. **Connect region list.** Installed CLI 0.0.17 `deployment create --help` lists five regions (GCP and AWS); the published CLI docs list only the three GCP ones. Default stays `us-central1.gcp`; `CLOUD_IDENTIFIER` is derived from the region (`gcp-us`, `gcp-eu`, `gcp-au`, `aws-us`, `aws-eu`).
