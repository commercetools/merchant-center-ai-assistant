## ADDED Requirements

### Requirement: Generated Nimbus surface manifest
`nimbus-surface.generated.ts` SHALL be generated by `scripts/generate-nimbus-surface.mjs` from the installed `@commercetools/nimbus` package and SHALL export `NIMBUS_VERSION`, the compound components with their parts, the component-with-parts map and the list of exported names. The file SHALL be committed, and a test SHALL fail when the manifest `NIMBUS_VERSION` differs from the Nimbus version the frontend scope uses.

#### Scenario: Version exported
- **WHEN** the manifest is imported
- **THEN** `NIMBUS_VERSION` is a semver string

#### Scenario: Stale manifest
- **WHEN** the installed Nimbus version differs from `NIMBUS_VERSION`
- **THEN** `npm run check:nimbus-surface` exits non-zero with the regenerate command

### Requirement: Scope lists derived, audited and compound-aware
`nimbus-scope.ts` SHALL build the scope bullets, tool-description lines and compound reference from the manifest. A compound component SHALL be marked with `*` and its parts listed. An audit function SHALL report names that are unknown to Nimbus or are not renderable.

#### Scenario: Compound marker
- **WHEN** `PageContent` is a compound component in the manifest
- **THEN** the bullets contain `PageContent*` and the reference contains `PageContent` with `.Root .Column`

#### Scenario: Audit clean
- **WHEN** `auditNimbusScope()` runs
- **THEN** `unknown` and `notComponents` are empty

### Requirement: Prompt contents
`getCommercetoolsUIPrompt(ctx)` SHALL describe: the tool, that no import statements are written, the in-scope names, the compound rule, the Nimbus MCP lookup tools (`list_components`, `get_components`, `get_tokens`, `search_icons`, `search_docs`, `get_docs_page`, `migrate_from_uikit`) and the instruction to batch lookups into one `get_components` call, that pages cannot run SQL (run `query_aggregated_data` in the conversation and embed rows), and that data sources are read-only GraphQL. The prompt SHALL use the shared tool-name constants and SHALL NOT mention the Nimbus tools when the `nimbus` source is disabled.

#### Scenario: Nimbus enabled
- **WHEN** the `nimbus` source contributed tools
- **THEN** the prompt contains the lookup tool names

#### Scenario: Nimbus disabled
- **WHEN** the `nimbus` source is disabled (`NIMBUS_MCP_ENABLED=false`)
- **THEN** the prompt omits the "Look up the Nimbus API" section and still lists the in-scope names

#### Scenario: Examples do not teach the bug
- **WHEN** fenced code and example `componentBody` strings in the prompt and tool description are scanned
- **THEN** none opens a compound component by its bare name

### Requirement: Custom view isolation
The `commercetools-ui` source SHALL be excluded from H's custom-view orchestrator selection (which selects only `commercetools` and `commercetools-knowledge`).

#### Scenario: Custom view
- **WHEN** a custom-view request is orchestrated
- **THEN** `create_composed_page` is not in the tool set
