## Glossary

- **Offload**: writing a large tool result into BigQuery and giving the model a table reference instead of rows.
- **Analyzer**: a small LLM call that answers "does this turn need aggregation over the result?".
- **Dry run**: a BigQuery job that validates and plans the query without running or billing it; returns statistics.
- **`maximumBytesBilled`**: per-job cap on billed bytes; exceeding it fails the job before execution.
- **Streaming insert (`insertAll`)**: row-at-a-time ingestion, immediately queryable, needs billing.
- **Files endpoint**: `GET /service/files/:sessionId/:fileName`, the only way a browser reads a stored image in `private` mode; it streams the object after the normal Merchant Center session check.
- **Blob URL**: `URL.createObjectURL(blob)` result used as `<img src>` after the frontend fetched the image with `forwardToFetch` (a plain `<img>` cannot carry the forward-to JWT).
- **Public access prevention (PAP)**: bucket setting that blocks any `allUsers`/`allAuthenticatedUsers` grant.
- **UBLA**: uniform bucket-level access (disables object ACLs).
- **Session table**: a BigQuery table registered on a chat session via the offload.
- **Cleaner**: component registered to run when a session is deleted.
- **MCP `CallToolResult`**: `{ content: [{type:'text', text}], isError, structuredContent? }`.

## Decisions

**DL-1. SQL guard = BigQuery dry run (`statementType`, `referencedTables`) + job caps; no home-made SQL parser as the primary control.** The server is the only authority on what a query does (views, wildcards, comments, `EXECUTE IMMEDIATE`). Alternatives: (a) regex/tokenizer allow-list - rejected as primary: bypassable by comments, quoting, scripts; kept as a cheap pre-filter (single `;`-free statement) and as the fallback if dry runs omit `referencedTables` (OQ-L1); (b) separate read-only service account and a dataset with only session tables - strongest but needs more IAM setup and does not stop cross-session reads (all sessions share the dataset); mentioned in README as optional defence in depth.

**DL-2. Enforce session ownership via the session's registered tables**, not via naming conventions. Alternative: per-user dataset - rejected (dataset sprawl, IAM). Consequence: tools must be per-request factories; the registry is G's.

**DL-3. Row/size caps: 500 rows, 256 KB, `maximumBytesBilled` 200 MB (constants).** Rationale: session tables are results of a few MCP calls (MBs); BigQuery bills a 10 MB minimum per referenced table, so 200 MB covers about 20 tables. Alternative: configurable env - rejected for v1 to avoid config creep; constants live in one file and are tested.

**DL-4. Table expiry 7 days.** Alternative: dataset default expiration - rejected: dataset is created by the owner and may host other tables. Session deletion remains the primary cleanup.

**DL-5. G's `registerSessionCleanupHook(fn(session))` is the seam (G design D-G6); L registers two hooks.** G's contract passes the whole session (`id`, `userId`, `temporaryTables`), which is all the hooks need. Alternative: L patches `chat.service` deletion - rejected: cross-change coupling.

**DL-6. Private bucket, images streamed by the backend (owner decision Q9); no signed URLs, no resolver.** The stored part URL is the service-relative path `/files/{sessionId}/{fileName}`; the route `GET /service/files/:sessionId/:fileName` sits behind the verified Merchant Center session (change D: forward-to JWT, audience policy `forward-url-full-path`, so the full path including the two parameters is covered) and the session ownership rule of change G (owner, or an administrator listed in `ADMIN_USER_IDS`, `req.user.isAdmin`, for the backoffice transcript view; everyone else gets 404 `File not found`). A plain `<img src>` cannot carry the forward-to JWT, so the frontends fetch the bytes with `forwardToFetch` and show a blob URL (changes P, S; R never shows service images). Alternatives: (a) V4 signed URLs + re-signing on read - rejected by the owner (bearer links, 7-day cap, resolver plumbing in G/N); (b) cookie auth - not available behind the gateway; (c) public objects - exposes user content, works only with `IMAGE_URL_MODE=public`. Consequences: the service streams image bytes (bounded by the 10 MB cap; Connect instance memory is unaffected because it is a stream, not a buffer) and each image view is one authenticated request through `/proxy/forward-to` (binary passthrough is **unverified**, spike 6.4, OQ-L7).

**DL-7. Read images for the model via the Storage API and downscale** rather than HTTP fetch (the bucket is private and the stored URL is relative; H's history loader applies `ImageUploader.toModelMessages` to every model-bound message list, so a relative `/files/...` URL never reaches Gemini). `sharp` stays (native) - alternative `jimp` rejected (slow); if `sharp` fails on Connect, skip downscaling (images capped at 10 MB anyway).

**DL-8. Streaming insert stays; on the specific free-tier error fall back to a load job.** A small adapter `writeRows` tries `insert` chunks and on `Streaming insert is not allowed in the free tier` switches to `table.createWriteStream({sourceFormat:'NEWLINE_DELIMITED_JSON'})` once per process (logged). Alternative: always load jobs - rejected: seconds of latency per offload on the chat critical path.

**DL-9. CSV neutralisation prefixes `'`** (OWASP CSV injection guidance) for strings starting `= + - @ \t \r` except numbers. Alternative: leave as is (legacy) - rejected: data from commercetools (customer names, product titles) is attacker-influenceable.

**DL-10. Analyzer unchanged** (parity), including the known unused prompt arguments.

**DL-11. Bootstrap of dataset and bucket: create idempotently on first use when permitted; otherwise report an actionable message.** `ensureDataset()` (called when a table create answers 404 `Not found: Dataset`, and by `checkGcpAnalytics()`) runs `bigquery.createDataset(datasetId, { location })` and treats 409 `already exists` as success. `ensureBucket()` (called when the first object write answers 404 `NoSuchBucket`, and by `checkGcpAnalytics()`) runs `storage.createBucket(name, { location, iamConfiguration: { uniformBucketLevelAccess: { enabled: true }, publicAccessPrevention: mode === 'private' ? 'enforced' : 'inherited' } })` and treats 409 as success; in `public` mode it then adds the bucket-level binding `allUsers` -> `roles/storage.objectViewer`. Both are memoised per process; a 403 is memoised as a failure with the message from a closed list that names the missing permission and gives the manual command (`bq --location=<loc> mk -d <project>:<dataset>`, `gcloud storage buckets create gs://<name> --location=<loc> --uniform-bucket-level-access --public-access-prevention`). **Roles.** BigQuery: `roles/bigquery.dataEditor` on the **project** includes `bigquery.datasets.create`, so the recommended grant is project-level `dataEditor` + `jobUser`. Storage: **recommended (least privilege) = pre-create the bucket and grant `roles/storage.objectAdmin` on it only**; **alternative (the service creates the bucket) = `roles/storage.admin` on the project** (`storage.buckets.create`, and `setIamPolicy` for public mode), or a custom role with `storage.buckets.create` + `storage.buckets.get` next to `objectAdmin`. A bucket is only created when absent; an existing bucket's settings are never changed (mismatches are reported by the self-check). Alternatives rejected: a mandatory Terraform/gcloud step (extra manual burden for a connector installer), or silent creation with overly broad roles at runtime.

**DL-12. `public` mode = bucket-level IAM on a uniform-access bucket, not per-object ACLs.** ACLs are disabled on uniform buckets (finding 15); `IMAGE_URL_MODE=public` therefore requires the bucket binding `allUsers: roles/storage.objectViewer` and public access prevention not enforced. Stored URL: `https://storage.googleapis.com/{bucket}/{object}`; objects carry `Cache-Control: public, max-age=3600`. The files route still works for these images. This mode makes every generated image world-readable - documented as not recommended.

## Risks / Trade-offs

- **[Dry run may not list `referencedTables`]** -> spike 3.1; fallback tokenizer + `defaultDataset` + SA permissions.
- **[Dry-run doubles job creation per query]** (+~300 ms) -> acceptable; dry runs are free.
- **[All users share one dataset and SA]** -> session-bound guard; README recommends a dedicated project/dataset for the assistant.
- **[Billing must be enabled]** -> README + manual step; load-job fallback (DL-8) keeps sandbox projects working.
- **[Gateway may not pass binary bodies / may cap response size]** (`/proxy/forward-to`, OQ-L7) -> spike 6.4 measures a 1 MB PNG; fallback if it fails: return the image as a `data:` URL inside a JSON envelope from a second route variant (`?encoding=base64` is NOT allowed through the gateway - query strings are forbidden by O's forward-to rules, so a separate path `/files/:sessionId/:fileName/base64` would be added as row 29 of G's route table). Decide after the spike.
- **[A broad `roles/storage.admin` is needed for auto-creating the bucket]** -> least-privilege path documented first (pre-create bucket + `objectAdmin`); the service never needs more than `objectAdmin` at runtime.
- **[Feedback snapshots (N) and backoffice transcripts (Q) contain relative file URLs]** -> they stay valid for as long as the session exists and are loaded through the same blob hook; after session deletion the image is gone (404 placeholder).
- **[Public mode misconfigured]** (`IMAGE_URL_MODE=public` on a bucket with public access prevention, or `private` on a public bucket) -> self-check does an anonymous `HEAD` on a probe object and warns with the exact fix command.
- **[`sharp` native build on Connect]** (R-L4) -> make downscaling optional (try/catch import), test in sandbox.
- **[Prompt injection steering SQL]** -> guard limits blast radius to the session's own tables.
- **[Serialization of BigQuery types]** (`BigQueryDate`, numerics) -> keep the JSON round trip from legacy.
- **[Analyzer cost/latency per tool call]** -> unchanged; size gate bypasses the model for huge results.

## Migration Plan

New deployment, no data. Prerequisites in GCP: project with billing, APIs enabled, SA roles (Q9, see DL-11). The dataset and the bucket do NOT have to exist beforehand: `postDeploy` (change U) calls `checkGcpAnalytics()` which creates them idempotently when permitted and otherwise reports what to do; the first use at runtime does the same lazily. The check also proves: can create+drop a probe table, can write+delete a probe object, the object is not anonymously readable (private) or is (public). Rollback: unset offload by returning raw results (feature flag `ANALYTICS_OFFLOAD` is not introduced; failure already degrades to raw).
